# 三条路线各自离工业级还差哪些、接下来具体怎么做

[doc/11](11-industrial-gap-and-roadmap.md)讲的是三条路线**共同**的差距
(实验闭环、团队、合规这些结构性的)，这篇补上**每条路线各自单独的**缺口——
数字全部来自数据库真实查询(不是回忆)，查询方式见本文末尾，随时可以自己
重新跑一遍核对。

## 路线A(SHP2/SOS1)：三条里结构数据最扎实，但一步验证没做

**已经做对的**：5EHR(SHP099/SHP2)、6SCM(BI-3406/SOS1)都是真实下载+清洗的
共晶结构，16个候选分子真实对接出有区分度的分数，决策批次也真实跑完选出
10个。这是三条路线里"结构生物学输入"最扎实的一条(配体HETATM确认存在，
不需要像路线C那样先走计算突变)。

**真正的缺口**：

1. **(已完成)SHP2/SOS1各自单独做过retrospective验证了，结果差异很大**——
   DUD-E不收录这两个靶点，改用真实ChEMBL数据：SHP2(CHEMBL3864)验证出
   AUC=0.575(比EGFR的0.69弱)，SOS1(CHEMBL2079846)验证出AUC=0.878(比
   EGFR还强)。同一条路线、同一套Vina对接代码，在两个不同受体上的区分
   能力差了一大截，不能笼统地说"路线A的对接可信度"，要按受体分开看，
   详见下文两节。
2. **环节5(选择性引擎)完全没跑**——这恰好是设计文档原话"整条管线最该
   投入算力的地方"，而路线A因为变构位点结构清楚、共晶多，被认为是三条
   路线里**FEP最友好**的一个(`competitive-landscape.md`里的原话)，
   意味着如果要在三条路线里选一条先投入真实FEP算力，路线A性价比最高，
   但目前这个优势完全没兑现成实际跑过的结果。
3. 骨架仍是`illustrative_only`，没有专家review；FTO仍是placeholder。
4. **(已部分补上)6SCM(SOS1)的受体一直没真正准备过**——之前"结构数据最
   扎实"这个说法只兑现了一半：5EHR真实对接了16个候选，但6SCM从来没对接
   过任何东西。现在补上了receptor PDBQT准备，并做了一次BI-3406自我
   redocking的sanity check(真实-8.95 kcal/mol，姿态尺寸合理)，但16个
   候选本身依然没有真正对接进6SCM——而且这16个候选的化学型是照SHP099
   设计的，不是照BI-3406设计的，直接对接6SCM的意义更多是"交叉结合风险
   检查"，不是"验证SOS1路线本身"，详见
   [route-a-shp2-sos1.md](routes/route-a-shp2-sos1.md)。

## 路线B(降解剂)：三条里客观上最落后，不是态度问题，是真实的方法学卡点

**已经做对的**：4TZ4(CRBN+来那度胺)真实共晶结构、E3配体真实Ki查证属实
(来那度胺≈3100nM)、三元复合物几何筛选真实跑过一整套(warhead对接+Kabsch
刚体变换追踪+500次随机采样)，还诚实产出了一个有统计量支撑的负向发现
(0/500次找到几何兼容姿态)。

**真正的缺口，比另外两条路线更本质**：

1. **10个候选分子从来没有被对接过——已经补上，过程中发现一个值得记录的
   方法学陷阱**。第一次尝试直接把10个完整的双功能分子(warhead-linker-
   E3配体，MW 700-900)整个扔给Vina对接，技术上全部"成功"
   (-7.96~-9.73 kcal/mol，看起来分数还不错)——但检查对接出来的姿态
   发现这些分数**不能信**：真实姿态的空间延展只有约10-16Å，说明Vina
   把整个又长又大的分子硬折成一个紧凑小球塞进了给小分子设计的对接盒子，
   不是真实的PROTAC结合模式(warhead在口袋里、linker和E3配体伸到溶剂里
   够向另一个蛋白)。这组数字已经从数据库删掉，没有留着当真实结果用。

   正确做法：10个候选共享同一个warhead(`demo_warhead_from_route_c_scaffold`)，
   单独把这个warhead片段(接口端补氢封闭)拿去对接，真实分数**-8.19
   kcal/mol**——这个量级和路线A/C真实候选的分数相当，说明warhead本身
   结合EGFR口袋没问题。已经用这个分数覆盖性地写入`funnel_scores`(10个
   候选都是同一个值，因为它们的target-engagement模块是同一个片段)。
   **诚实的边界**：这仍然只是L1对接分数(kcal/mol)，不是真实的
   `warhead_kd_nm`(纳摩尔级Kd)——把-8.19 kcal/mol硬换算成一个Kd数字
   拿去跑后面的hook effect/决策算法，会赋予这个粗糙估计不该有的精确度
   (L1误差量级±2.5 kcal/mol，换算成Kd的不确定度有七十多倍)，本仓库没有
   这么做，第2点的决策缺口依然存在。
2. **没有任何决策批次**——`decision_rounds`表里压根没有路线B的记录，
   原因是`warhead_kd_nm`这个核心输入始终缺失(需要环节4对接/FEP产出，
   而环节4本身都还没跑)，而本仓库的原则是"没有真实Kd就不编一个假的去
   跑决策算法"，所以宁可留空也不跑一个基于假数据的决策。
3. **三元复合物的采样策略已经被证明走不通**：均匀随机刚体采样500次，
   0次找到兼容姿态，不是运气不好，是方法学本身的限制(两个蛋白表面各自
   很窄的连接点，靠随机转向撞上的概率天然很低)。这是一个需要**做决定**
   的真实分叉点，不是继续调参能解决的：
   - 要么投入做约束采样(朝着已知exit vector大致方向偏置采样，而不是
     均匀随机)，工程量不小；
   - 要么接受"轻量版走不通"这个结论，正式把路线B的三元复合物预测标记
     为"需要PatchDock或等价工具，当前搁置"，先把前面两个缺口(对接+决策)
     补上，不被三元复合物这一个最难的子问题卡住整条路线的进度。
4. CNS MPO公式按传统小分子校准，套在beyond-Ro5的双功能分子上系统性
   失准(已知局限，`run_bifunctional_round.py`的输出已经标注过，没有修)。

## 路线C(四代TKI)：三条里最成熟，但也暴露了最多"看起来完整、实际没验证"的缝

**已经做对的**：324个候选分子完整走过标准化→枚举→ADMET→决策全流程，
24个真实对接分数(交叉验证两个基因型，Spearman一致)，PyRosetta真实计算
出了主要基因型(L858R/C797S)原本没有晶体结构的计算模型，刚做完的DUD-E
retrospective验证(AUC=0.69)。这是三条路线里唯一有完整端到端参照实现的。

**真正的缺口**：

1. **retrospective验证的覆盖范围要讲清楚边界**：这次验证的是"Vina对
   EGFR这个蛋白家族/口袋类型有没有区分力"，用的542个真实活性分子基本是
   针对野生型/经典突变的历史数据，**几乎不包含专门针对C797S三重突变体系
   测过的化合物**(这是数据层面的硬约束——文献本身稀疏，不是没去找)。
   AUC=0.69这个数字不能直接说成"本仓库对C797S的预测有69%准确"，这是
   常见的过度引用错误，要主动避免。
2. **纠正上一版这里的一个不准确说法——已经真实补上，结果如下**。上一版
   写的是"路线C核心机制是共价结合，但从没在真实候选上跑过几何判据"，
   这句话本身不准确，查证后更新：**真实的324个候选分子用的
   `demo_aminopyrimidine_biphenyl`骨架，`chemistry_route.primary`配置的
   是`reversible_orthosteric`(可逆正构，不是共价)，`covalent_warhead_enabled:
   false`——这批候选分子根本不含任何共价弹头，没有东西可以测几何**。
   共价(`covalent_new_site`)只是配置里的backup选项，从未真正落地到任何
   一个候选分子的结构上。真正含共价弹头的只有奥希替尼这一个外部参照分子，
   而本仓库现有的全部C797S受体结构(6LUD及其衍生的PyRosetta模型)里797位
   都已经突变成Ser——这正是C797S耐药机制本身，意味着这些结构里根本没有
   真实的Cys-SG可供测量。

   **于是真实做的是**：新增`core/covalent.py::extract_michael_acceptor_geometry()`
   (从一个真实对接姿态里，纯几何识别丙烯酰胺端位烯烃碳+量出到指定亲核
   原子的距离/角度，不依赖PDBQT不可靠的CONECT信息，4个单测验证了识别
   逻辑本身)，用真实PDB **4ZAU**(标题"AZD9291 COMPLEX WITH WILD TYPE
   EGFR"，SEQADV确认790/797位都未突变，Cys797完整保留)，把奥希替尼当
   完整小分子非共价对接进去(真实Vina打分-7.134 kcal/mol)，量出的真实
   几何：**弹头碳到Cys797-SG距离6.05Å，攻击角155.1°**(偏离105°目标
   50.1°，超出±15°容忍区间，`evaluate_attack_geometry()`判定
   `geometry_ok=False`)。

   **这个结果本身是一个有价值的诚实负向发现，不是实现bug**：6.05Å已经
   远超共价反应可行的距离量级(真实反应前的encounter complex通常要在
   4Å以内)，说明普通非共价Vina对接**没有能力**把奥希替尼的弹头摆到真实
   会发生共价反应的那个姿态上——这完全符合预期，因为Vina的打分函数/
   搜索算法从头到尾都不知道"这个位置应该形成共价键"这件事，只会按
   非共价的形状/静电互补性去找一个能量最低的姿态，这个姿态可能和真实
   反应前体姿态完全不是一回事。这是一个真实、量化出来的证据，支撑了
   本仓库从一开始就强调的那句话："真实共价对接需要CovDock/Rosetta，
   普通Vina对接做不到"——现在不只是定性地这么说，有具体数字了。
   完整脚本见`scripts/run_covalent_geometry_check.py`。
3. `fto_status`在数据库里全部是NULL，不是"placeholder_not_real"这个
   占位值，说明`check_fto()`从未真正对任何一个候选分子持久化执行过。
4. 赛道拥挤的外部现实没变：3个真实项目同时在跑(silevertinib/
   tigozertinib/BBT-176)，其中silevertinib已经公开披露了本该是护城河的
   CNS渗透真实数据。

## 2026-10补充：路线C的EGFR专属retrospective验证——详细结果(原doc/14，已合并)

这是[doc/11第5节](11-industrial-gap-and-roadmap.md)说的"第一关"——在继续
往这个仓库里加新指标、砸更多算力之前，先拿已知答案检验现有方法本身准不准。

**方法**：DUD-E的EGFR靶点数据集，全部542个真实已知活性化合物(来自ChEMBL)
+ 从35050个诱饵分子里随机抽样2000个(固定种子42，抽样是单机算力限制，
不是数据不够——DUD-E免费，这次没有花钱买数据)。受体用DUD-E官方提供的
(基于PDB 2RGP)，不是本仓库自己的6LUD/C797S突变模型——**故意**这么选，
为了先单独检验"Vina+meeko这条对接流水线本身"的区分能力，不和"本仓库
自己做的受体准备/突变建模"这个变量混在一起。真实跑了7小时11分钟，
2542个全部成功。

**真实结果**：

| 指标 | 数值 |
|---|---|
| AUC(ROC曲线下面积) | **0.6913** |
| n_actives / n_decoys | 542 / 2000 |
| 活性分子平均打分 | -9.70 kcal/mol(中位数-9.61) |
| 诱饵分子平均打分 | -8.89 kcal/mol(中位数-8.97) |
| 富集因子 EF@top1% | 3.56倍(前25个里19个是真活性分子) |
| 富集因子 EF@top5% | 2.99倍 |
| 富集因子 EF@top10% | 2.42倍 |
| 富集因子 EF@top20% | 1.98倍 |

**解读**：有真实区分能力，但弱到中等。真实活性分子比诱饵平均打分低
0.81 kcal/mol(方向对，跨2542个样本统计出来的，不是偶然)；AUC=0.69比
随机(0.5)好但没好很多(`core/validation.py::_interpret_auc()`判定"弱区分
能力，比随机好但不多，排序结果慎用"，这个档位不是自己瞎定的，是标准ROC
解读惯例：0.9+优秀/0.7+有意义/0.55+弱/0.45-0.55随机)；富集因子头部更准
(EF@1%=3.56倍逐渐衰减到EF@20%=1.98倍)，是健康的虚拟筛选行为模式。

**对本仓库的意义**：Vina+meeko这条流水线在EGFR上不是瞎猜，验证了"L1对接
只能粗筛、不能精排"这条设计原则是对的方向——有信号，但信号不够强，不能
拿它去做"前10名谁排第1"这种精细排序。**没有验证到的部分**：这次用的是
DUD-E官方野生型/经典突变受体，**没有验证本仓库自己的C797S突变模型本身
对不对**；542个活性分子也几乎不包含专门测过C797S三重突变体系的化合物——
这次验证的是"Vina对EGFR这个蛋白家族有没有区分能力"，不是"对本仓库真正
关心的C797S耐药体系有没有区分能力"，两者不能混为一谈。

原始数据：`validation/dude_egfr/results/docking_scores.csv`；日志：
`validation/dude_egfr/results/run.log`；脚本：`scripts/run_dude_validation.py`。

## 2026-10补充：路线A的SHP2专属retrospective验证——真实跑完了，结果比EGFR弱

查证后发现DUD-E的102个靶点里**没有SHP2(PTPN11)也没有SOS1**(完整列表
已核对，不是猜的)，这类较新的变构靶点不在2012年发表的DUD-E原始收录范围
内。ChEMBL的API一开始返回500错误(两条独立路径验证过是服务端故障)，
**隔了一天后再查，服务恢复了**，于是改用真实ChEMBL数据跑了一遍。

**方法**：查CHEMBL3864(人源PTPN11/SHP2)真实IC50/Ki记录，过滤掉27条标记
有质量问题的，按分子去重取中位数，active(IC50≤1μM)和inactive(≥10μM)
分别筛出1420和279个——**真实分布和DUD-E正好相反**(DUD-E是少活性多诱饵，
这里是多活性少无效)，这是药化文献本身的发表偏向，不是抽样偏差。为控制
对接总耗时，active随机抽样(种子42)到400个，inactive全部保留(更稀缺的
一类)，总共679个真实化合物，对接进真实5EHR受体(SHP099变构tunnel位点，
box中心从真实配体坐标量出来的)。

**真实结果**：674个成功(5个配体准备失败，占比0.7%，不影响结论)。

| 指标 | 数值 | 对比EGFR那次(DUD-E) |
|---|---|---|
| AUC | **0.575** | 0.69 |
| n_active / n_inactive | 395 / 279 | 542 / 2000 |
| active平均打分 | -8.42 kcal/mol | -9.70 kcal/mol |
| inactive平均打分 | -8.41 kcal/mol | -8.89 kcal/mol |
| EF@top5% | 1.30倍 | 2.99倍 |
| EF@top20% | 1.15倍 | 1.98倍 |

**AUC=0.575，比EGFR那次(0.69)明显更弱**，几乎只比随机好一点
(`core/validation.py`判定"弱区分能力，比随机好但不多")。active和inactive
的平均打分几乎一样(-8.42 vs -8.41)——这次对接**基本没能把真实有效和真实
无效的化合物分开**。

**为什么会更弱，有两个很可能的原因，脚本docstring提前就标注过这个风险**：

1. **这里的"无效"分子是真实测过的弱效化合物，大概率是同一个优化系列里
   活性分子的结构类似物**，不是DUD-E那种故意选得"性质像但结构不像"的
   诱饵——结构越像，对接分数也越难区分开，这是一个比DUD-E**更难**的任务，
   AUC更低不代表方法更差，可能只是题更难。
2. **更可能的解释：绑定位点不匹配**。ChEMBL里"SHP2抑制剂"这个大类历史上
   混杂两种完全不同机制的化合物——5EHR代表的变构tunnel位点(SHP099那类)，
   和另一类直接堵催化半胱氨酸的活性位点抑制剂。本次没有逐个化合物查文献
   确认绑定位点，如果真实active里混进了不少活性位点抑制剂，它们被强行
   对接到tunnel位点，打分自然和真正无效的分子差不多——不是方法没有区分
   力，是"问错了口袋"。

**这个结果诚实地说明什么**：路线A目前16个真实候选分子的对接分数，**不能
假定和EGFR那次一样可信**——SHP2这个靶点上，用5EHR这个受体做的Vina对接，
区分能力明显更弱，排序结果要比路线C更谨慎地只当粗筛用，不要当排名用。

### 2026-10再补充：用化学相似度低成本检验了"问错了口袋"这个猜测——没有支持这个猜测

逐个化合物查文献确认绑定位点工作量很大，先用一个便宜很多的替代方法初步
检验：**真实变构tunnel位点抑制剂的"原型化合物"SHP099**结构已知且公开
(`CC1(N)CCN(c2cnc(-c3cccc(Cl)c3Cl)c(N)n2)CC1`，经ChEMBL
`CHEMBL4060033`核对formula/MW完全一致，不是凭记忆写的)，用Morgan分子
指纹算674个真实化合物各自和SHP099的Tanimoto相似度，按相似度分组后分别
算AUC——如果"问错了口袋"是真实原因，相似度高(更像变构化学型)的那组AUC
应该明显更好。

**真实结果**：不同相似度阈值下都没有看到这个模式——

| 相似度阈值 | 更像SHP099组AUC | 更不像SHP099组AUC |
|---|---|---|
| ≥0.15 | 0.49(和随机没区别) | 0.43(方向还反了) |
| ≥0.20 | 0.52(和随机没区别) | 0.56 |
| ≥0.25 | 0.50(和随机没区别) | 0.59 |
| ≥0.30 | 0.54 | 0.58 |

**结构上更像SHP099的那组，AUC反而不比"不像"那组好，部分阈值下还更差**——
这和"问错了口袋"的猜测方向相反，没有支持这个解释。另外检查了一个更
简单的混淆因素：active和inactive的分子量有没有系统性差异(更大的分子
容易在Vina打分里"作弊"般地占优)——active平均分子量456 vs inactive平均
424，确实略大，但分子量和对接分数的相关系数只有0.014，基本没有关联，
这个混淆因素也排除了。

**所以目前最可信的解释，回到第一条**：这里的"无效"分子是同一优化系列的
真实结构类似物，比DUD-E刻意挑的"性质像但结构不像"的诱饵本质上更难靠
对接分数区分开——这更像是"任务比EGFR那次更难"，不是"受体/口袋选错了"。
这个结论建立在两次真实的排除性检验上，不是没查就归因，但也没有做到
"逐个化合物查文献确认"这种能100%排除疑虑的程度——如果以后要彻底搞清楚，
仍然需要那个更贵的人工核对步骤。

原始数据：`validation/chembl_shp2/results/docking_scores.csv`；脚本：
`scripts/run_chembl_shp2_validation.py`。

## 2026-10再补充：路线A的SOS1专属retrospective验证——真实跑完了，结果比SHP2和EGFR都强

6SCM(SOS1)受体之前只做过BI-3406的自我redocking sanity check，没有做过
真正的retrospective验证。用和SHP2那次完全一样的方法，查CHEMBL2079846
(人源SOS1)真实IC50/Ki记录，过滤掉1条标记有问题的，active(IC50≤1μM)和
inactive(≥10μM)分别筛出776和19个——**负例比SHP2那次(279个)少得多**，
这是SOS1这个靶点真实的研究历史决定的(主要是2018年后KRAS相关研究驱动，
比SHP2年轻得多，"做出来但失败"的化合物远没有被详细记录过)，不是抽样
问题，跑之前脚本docstring里就提前标注了这个会削弱负例统计功效的风险。
active随机抽样(种子42)到400个，inactive全部保留(19个)，总共419个真实
化合物，对接进真实6SCM受体(box中心取自真实BI-3406晶体坐标质心，这个
质心这次会话早些时候已经用BI-3406自我redocking验证过能还原出真实姿态)。

**真实结果**：419个全部成功，0个失败。

| 指标 | 数值 | 对比SHP2那次 | 对比EGFR那次(DUD-E) |
|---|---|---|---|
| AUC | **0.878** | 0.575 | 0.69 |
| n_active / n_inactive | 400 / 19 | 395 / 279 | 542 / 2000 |
| active平均打分 | -9.10 kcal/mol | -8.42 | -9.70 |
| inactive平均打分 | -7.66 kcal/mol | -8.41 | -8.89 |

**AUC=0.878，是这个仓库跑过的三次retrospective验证里最强的一次**——
比EGFR那次(0.69)还要高，和SHP2那次(0.575，几乎等于随机)完全不是一个
量级。active和inactive的平均打分差了1.44 kcal/mol，方向正确(真实有效
的分子打分更负)，不是像SHP2那次几乎分不开。

**两个混淆因素排除检查(按SHP2验证那次用过的同一套方法)**：
1. **分子量会不会是作弊因素**：active平均分子量470.8，inactive平均
   499.7——inactive反而更大，如果"更大的分子天然打分更负"是主导因素，
   结果应该反过来，说明这不是分子量在驱动这次的区分度。
2. **打分和分子量的皮尔逊相关系数只有0.094**，基本没有关联，进一步
   确认这次的AUC不是分子量混淆出来的假象。

**EF(富集因子)这次刻意不作为主要指标汇报，原因要讲清楚**：EF@top1%/5%/
10%算出来都是1.05，乍看很差，但这是这次数据**类别比例本身极端倒置**
导致的数学结果，不是方法失效——400个active占全部419个化合物的95.5%，
随便抽一批"前N%"几乎必然大多数是active，`max_possible_ef`这次算出来
本身就只有1.05(富集因子的理论上限由正例比例决定，正例占比越高、能
富集的空间越小)，EF实际达到了这个理论上限，意味着**该做到的都做到了，
只是这个指标在"正例占绝大多数"的场景下本身就没有信息量**——这正是为
什么本仓库一直强调EF是"排名最前面一小段里浓度有没有提高"的指标，前提
是正例本来就是少数；这次反过来了，AUC才是这次更可信的指标。

**这个结果诚实地说明什么**：路线A同一条代码路径(`core/docking.py`+Vina)
在不同受体/靶点上的表现差异很大——SOS1(6SCM)上区分能力明显强于SHP2
(5EHR)，也强于EGFR(DUD-E的ATP位点)。目前没有做过逐化合物查文献确认
"SOS1的ChEMBL数据有没有混进不同结合机制"这类检查(SHP2那次做过、没支持
"问错口袋"这个猜测)，所以不能完全排除这次结果部分得益于SOS1数据集本身
更"干净"(单一结合机制，没有SHP2那种变构/催化位点混杂的历史问题)，但
至少可以诚实地说：**如果要在路线A内部选一个受体优先投入下一级验证
(MD/FEP)，这次的真实数据支持优先选SOS1而不是SHP2**，这和之前"路线A
整体不如EGFR可信"的笼统结论不一样，需要按受体分开看，不能一概而论。

原始数据：`validation/chembl_sos1/results/docking_scores.csv`；脚本：
`scripts/run_chembl_sos1_validation.py`。

## 2026-10再补充：三个之前标"需要第三方工具"的占位，真实装好并验证过了

这几个不是某条路线专属的，是共享引擎层面的真实升级，三条路线都能用：

1. **OpenMM+PDBFixer(蛋白短程MD)**：纯pip装进`.venv310`。真实跑过6LUD受体
   (4981原子)的能量最小化+10ps轨迹，CA骨架RMSD稳定在1.5-1.9Å，没有发散。
   `core/structures.py::run_protein_equilibration_md()`。顺带测出真实CPU
   吞吐量：10ps约86秒，换算下来真实项目需要的20ns×3副本量级要数十小时到
   几天——这是"需要GPU"这句话第一次有具体数字支撑，不是空口说。
2. **AmberTools+openff-toolkit(配体结合复合物MD)**：需要单独的conda环境
   (openff-toolkit需要Python≥3.11，pip在.venv310装不了)，用mamba(不是
   classic conda，后者卡在"Solving environment"20多分钟没解出来)几分钟内
   装好。真实跑过奥希替尼(**真实6LUD晶体坐标**，不是对接预测姿态)+C797S
   三重突变受体的复合物MD，配体RMSD均值1.54Å，没有飘出口袋——`core/
   md_stability.py::run_protein_ligand_complex_md()`。这证明工具链通了，
   不代表L3已经"真实可用"：还是皮秒级demo，`hinge_hbond_occupancy_pct`等

3. **AiZynthFinder(真实逆合成)**：纯pip装，额外下载约1.2GB真实模型+1700万
   ZINC建块库(路上第一次下载时ZINC库存文件被截断，重新下载才发现并修复，
   现在数据完整性已验证过)。真实跑出奥希替尼的4步合成路线，4个起始原料
   全部在真实库存里，其中`C=CC(=O)Cl`(丙烯酰氯)正是真实合成化学里安装
   丙烯酰胺弹头的标准试剂，和真实化学直觉吻合——`core/synthesis.py::
   run_retrosynthesis()`。详见[07](07-synthesis.md)。

这三个升级没有改变任何路线的"缺口"结论(路线B决策批次仍然缺、SHP2验证仍然
偏弱)，但把"这几个环节需要第三方工具"从占位声明变成了真实验证过的能力，
以后真要往这几个方向投入时，不需要再从零开始装环境。
